# From Question to Fidelity

## Concept value and comprehension
- **Question:** Do people understand what this is and want it?
- **Profile:** visual low, breadth narrow, depth shallow, interactivity low, data medium (realistic examples).
- **Medium:** storyboards, paper, simple Figma frames, a landing page or fake door for demand.
- **Fake:** everything behind the first screens.
- **Pitfall:** asking "would you use this?" (people over-report intent). Ask about current behaviour and observe reactions
  to concrete examples.

## Task flow usability
- **Question:** Can people complete tasks X, Y, Z? Where do they hesitate or fail?
- **Profile:** visual medium, breadth = tested tasks, depth high on those paths (alternates, errors), interactivity
  medium, data high and consistent.
- **Medium:** clickable Figma; ProtoPie or code if typing, search or filtering is central.
- **Fake:** back end, payments, real accounts.
- **Pitfall:** dead ends on likely wrong turns; data inconsistency between screens.

## Interaction feel
- **Question:** Does the gesture, animation, timing or input feel right?
- **Profile:** visual medium-high, breadth very narrow, depth deep for that interaction, interactivity high, data medium.
- **Medium:** ProtoPie, Origami, Framer, native or web code on the target device.
- **Fake:** everything except the interaction.
- **Pitfall:** testing on a laptop when the interaction is for a phone; recorded videos instead of hands-on use.

## Visual and brand response
- **Question:** How do people perceive the look: trust, premium, playful?
- **Profile:** visual high, breadth narrow, depth shallow, interactivity low, data realistic.
- **Medium:** high-fidelity comps, preference or five-second tests, desirability studies (e.g. product reaction cards).
- **Pitfall:** treating preference votes as usability evidence.

## Technical feasibility and performance
- **Question:** Can we build it? Will it be fast enough? Does the API support it?
- **Profile:** visual low-medium, narrow, deep, high interactivity, real data.
- **Medium:** coded spike by engineering with design pairing.
- **Pitfall:** making the spike pretty; it gets mistaken for a near-finished product.

## Stakeholder buy-in
- **Question:** Should we fund and prioritise this?
- **Profile:** visual high, breadth narrow (one story), depth shallow-medium, interactivity medium, curated realistic data.
- **Medium:** polished Figma prototype or a video, plus evidence (research clips, metrics).
- **Fake:** say clearly what is not real (AI, integrations), and give the estimate for building it.
- **Pitfall:** a polished demo creates the belief it's nearly done; frame it as a vision with known unknowns.

## Engineering handoff
- **Question:** What exactly should be built?
- **Profile:** visual high, broad, deep (all states), interactivity medium, edge-case data.
- **Medium:** design files with specs; prototype only for interactions that are hard to describe.
- **Pitfall:** using a prototype as the spec; prototypes skip states and edge cases.
