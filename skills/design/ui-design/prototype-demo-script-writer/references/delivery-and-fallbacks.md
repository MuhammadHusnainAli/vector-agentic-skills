# Delivery and Fallbacks

## Rehearsal

- Two full run-throughs on the real setup (room, laptop, screen share tool), timed.
- One run with a colleague asking hostile questions.
- Mark in the script where you pause for clicks or for the audience to read.

## Setup checklist

- [ ] Prototype opened at the start screen in presentation mode; all flows preloaded
- [ ] Notifications off (OS Do Not Disturb, chat apps quit), personal tabs closed
- [ ] Browser zoom and window size match the rehearsal; cursor highlighting on for remote audiences
- [ ] Test account logged in; data reset; time-sensitive data current ("today", "upcoming")
- [ ] Mobile demo: device mirrored, battery charged, auto-lock off, brightness up
- [ ] Network: wired or tested Wi-Fi; offline copy available
- [ ] Backup video of the click path (screen recording with voice) and screenshots in the slides
- [ ] Slides and prototype in the order of the script; links ready

## Remote demos

- Share a single window, not the whole screen.
- Narrate clicks ("I'm tapping Refund at the bottom right") because video lags.
- Slow down; pause after key moments; check in with a question halfway.
- Record if the audience agrees, for people who couldn't attend.

## Recorded walkthroughs

- 2-4 minutes; captions; the same story arc.
- Script word-for-word; record voice separately if needed.
- Show the cursor and use zoom-ins for small details.

## When things break

| Failure | Recovery |
|---------|----------|
| Prototype link won't load | Switch to the backup video immediately; don't debug live |
| Wrong screen or dead end | "Let me jump ahead": go to the next planned screen via the flow link |
| Question derails the flow | "Great question; I'll come back to it at the end" and note it |
| Running out of time | Skip to the outcome and the ask; offer a follow-up |
